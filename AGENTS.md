# AGENTS.md

`sndbnk` is a SoundCloud-style audio host: creators upload tracks, listeners play them through a
global player bar, and every creator gets a public profile reachable by path, by subdomain, or on
their own custom domain. SvelteKit + Svelte 5 runes, plain JS with JSDoc, Drizzle over SQLite,
better-auth, running on Bun.

## Hard constraints

- **Runtime is Bun, not Node.** `src/lib/server/db/index.js` imports `bun:sqlite`, so every command
  goes through Bun. `bun run dev` starts Vite on `http://localhost:5174`.
- **`#lib/...`, never `$lib`.** It is a package `imports` map in `package.json`; the `$lib` alias was
  removed from this project.
- **`safeRedirect()` from `#lib/server/safe-redirect`, never `redirect()` from `@sveltejs/kit`** in
  server code — Kit's version crashes under `svelte-adapter-bun`.
- **Plain JS with JSDoc types.** `jsconfig.json` sets `checkJs: false`; there is no TypeScript build
  step and no test runner.

## Commands

```sh
bun install
bun run db:migrate   # apply Drizzle SQL migrations (Bun migrator)
bun run nuke         # wipe DB + media + backups, remigrate (type "nuke" to confirm)
bun run dev          # Vite on http://localhost:5174
bun run build        # svelte-adapter-bun → build/index.js
bun run lint         # prettier --check .  (a few committed files fail; pre-existing)
bun run format       # prettier --write .
bun run auth:schema  # regenerate src/lib/server/db/auth.schema.js
```

Schema changes are **Drizzle generate + migrate**: edit [`src/lib/server/db/schema.js`](src/lib/server/db/schema.js),
run `bun run db:generate`, review SQL under [`drizzle/`](drizzle/), apply with `bun run db:migrate`.
Deploy backs up SQLite then migrates. Kit's CLI migrate/push uses `better-sqlite3` (Node-only), so
apply goes through [`scripts/migrate-sqlite.js`](scripts/migrate-sqlite.js). Standalone guide:
[docs/drizzle-migrations.html](docs/drizzle-migrations.html). Details:
[docs/data-model.md](docs/data-model.md).

## Environment

Variables are declared in [`src/env.js`](src/env.js) and read through `$app/env/private` /
`$app/env/public`. `.env.example` lists them all: `DATABASE_URL`, `ORIGIN`, `PUBLIC_BASE_DOMAIN`,
`BETTER_AUTH_SECRET`, `MEDIA_ROOT`, `BODY_SIZE_LIMIT`, `STORAGE_SECRET`, plus `PROTOCOL_HEADER` /
`HOST_HEADER` that the Bun adapter needs behind a proxy.

For dev: `ORIGIN=http://localhost:5174`, `PUBLIC_BASE_DOMAIN=localhost`.

**Every declared variable is required.** If your `.env` predates one, the app returns 500 on every
route at boot with `Invalid environment variables` — copy the missing line from `.env.example`.

- **Runtime is Bun, not Node.** The DB layer imports `bun:sqlite` (`src/lib/server/db/index.js`), so the app only runs under Bun. Start dev with `bun run dev` (Vite on `http://localhost:5174`). Standard scripts are in `package.json`.
- **Env vars** live in `.env` (see `.env.example`): `DATABASE_URL`, `ORIGIN`, `BETTER_AUTH_SECRET`. For dev, `ORIGIN=http://localhost:5174`. Both `.env` and the SQLite file are gitignored but persist across sessions via the VM snapshot.
- **DB schema:** `bun run db:generate` then `bun run db:migrate`. The SQLite file lives at `DATABASE_URL` (`local.db`). See [docs/drizzle-migrations.html](docs/drizzle-migrations.html).
- **Auth schema generation:** `bun run auth:schema` runs the better-auth CLI under Bun so it can load `bun:sqlite`. The generated `src/lib/server/db/auth.schema.js` is committed.
- **Lint:** `bun run lint` (`prettier --check`). A few committed files currently fail the check; that is pre-existing and unrelated to setup.
- **Core flow to smoke-test:** register at `/signup` or log in at `/signin`; both redirect to `/`, where the authenticated header shows the user and provides sign-out.

## Smoke test

`/signup` → `/library` (drop or pick an audio file; deck edit opens) → `/users/{username}` (play it,
confirm the global player bar survives navigation) → `/{username}/tracks/{slug}/` (like and comment) → sign out
from the header → `/signin` back in. Check any visual change in both light and dark mode.

## Svelte MCP

You have access to the Svelte MCP server (configured in [`.cursor/mcp.json`](.cursor/mcp.json)) with
comprehensive Svelte 5 and SvelteKit documentation. Use it rather than recalling API details.

- **`list-sections`** — call this first for any Svelte or SvelteKit topic. Returns titles,
  `use_cases`, and paths.
- **`get-documentation`** — after `list-sections`, fetch every section whose `use_cases` match the
  task. Accepts one or many sections.
- **`svelte-autofixer`** — run on any Svelte code you write, repeatedly, until it returns no issues or
  suggestions.
- **`playground-link`** — only after the user confirms they want one, and never for code written into
  this repo.

## Learned Workspace Facts

- Production runs on AWS Lightsail at `sndbnk.com` (SSH as `ubuntu@sndbnk.com`); the build uses `svelte-adapter-bun`, `systemd.service` runs `build/index.js` with Bun from `/var/www/sndbnk`, and Caddy proxies public traffic to the app on `localhost:3000`. Redis backs BullMQ async waveform jobs (`REDIS_URL`, typically `redis://127.0.0.1:6379`); run the worker with `bun run worker:waveform` locally and `sndbnk-waveform-worker.service` in prod (`BODY_SIZE_LIMIT` raised for long mixes). Mail uses an adapter (`MAIL_TRANSPORT=console|smtp` via `#lib/server/mail`); production SMTP is AWS SES Mail Manager; deploy preserves `MAIL_*` / `SMTP_*` (and Stripe keys). Auth mail covers welcome, Settings email-change verification, and forgot/reset password (`/forgot-password`, `/reset-password`); bootstrap a staff admin with `bun run createsuperuser` (`role = 'admin'`). `scripts/pull-prod.sh` SSHs in and rsyncs a local copy of the prod SQLite DB plus media.
- Shared chrome lives in `#lib/components/SiteHeader.svelte` and is included per page (not via a nested layout); global playback is `#lib/components/player/HeaderPlayer.svelte` in that header (the former footer `GlobalPlayerBar` was removed); header EQ is `#lib/components/player/EqPanel.svelte` / `EqSpectrum.svelte` plus `#lib/player/eq.svelte.js` / `eq-bands.js` / `audio-graph.svelte.js` (WebAudio graph; theme/volume/bands in localStorage); Milkdrop/`butterchurn` has three surfaces: default inline `#lib/components/player/InlineMilkdrop.svelte` on feed/library/profile/track (planet toggle; Pop out / Dock via persisted `mode`; hover-fade overlay controls without a titlebar, library deck variant unframed / can back the media player), floating `#lib/components/player/MilkdropWindow.svelte` in the root layout when mode is window (full-surface drag, EQ-matching resize handles, shared ~5px snap to player/EQ, spawn under player at player width; feed/profile/track sidebar docks reveal only after ~10px drag with slide+fade), and an ambient marketing-hero backdrop when audio is playing (curated mellower presets, dialable opacity) — keep primary + hero audio-synced without stuttering on enable/disable; canvas sizing must fill the parent (account for devicePixelRatio); EQ and viz raise z-index on focus so the active window stays on top.
- Creator profiles support bio, location, labeled external links, avatar, follows/reposts, and a stats-oriented sidebar whose panel titles match the feed discover style (short uppercase labels like Popular / Fans Also Like / Followers / Activity—no Discover/Audience eyebrows or duplicate meta numerals); when the sidebar is shown, external/social links render as a vertical Links panel directly below Stats (hero keeps the horizontal link list only when the sidebar is hidden); the main column uses Tracks | Likes | Listening History tabs (History is owner-only); empty libraries use plain copy like “No tracks have been uploaded yet”; only published tracks appear on public profiles.
- Tenant hosting needs a Route 53 `*.sndbnk.com` A record at the Lightsail IP (deploy smoke-tests it). Custom-domain verify accepts CNAME to `{user}.sndbnk.com` or A/AAAA/ALIAS to platform edge IPs (apex-safe); Settings shows those IPs; `example.com` ↔ `www.example.com` are paired for routing/TLS after one is active. Per-tenant `site` holds name/description/logo/OG/accent/`appearance` (`light`|`dark`|`user`)/`themePersona`/`themePalette`/`hideBranding` plus setup prefs (`siteIntent`, `wantBlog` / `wantEvents` / `wantEcommerce`, `setupCompletedAt`) for subdomain and custom-domain hosts (ignored on apex `/users/{username}`); accent/appearance/persona edit via Inspector Site theme or `PUT /api/sites/{id}/theme` and apply to public tenant pages + builder preview (not the SNDBNK listener theme); `#lib/builder/theme-persona.js` (colorjs.io) derives slot palettes from accent (`mono` / `analogous` / `complementary` / `split` / `soft` / `vivid`), and `themePalette` JSON holds optional slot overrides; owner apex routes `/sites/{id}` (first-run wizard) and `/sites/{id}/builder` are linked from the avatar Sites list when hosts exist—wizard fields go live on tenant hosts immediately; the builder bootstraps a `root` page and uses floating SNDBNK HUDs in `#lib/components/builder/` (Tools / Blocks / Inspector with Pages / Page / Blocks / Site tabs), page blocks in `#lib/components/blocks/` (optional layout `maxWidth`; previews under `#lib/components/block-previews/` and `/dev/block-previews`), and site-level header/footer separate from per-page blocks—builder chrome stays on platform accent while tenant `site.accent` / `appearance` style the preview; custom-domain profile sidebar is off by default with a master toggle plus per-card flags (`sidebarStats` / Fans Also Like / Followers / Activity), while subdomain hosts keep the full sidebar.
- Public tenant hosts render composed `site_page` records at `/` and flat paths through `#lib/server/site-page-public.js`; persisted site header/footer wrap each page, and `catalog.profile` places the creator's live audio profile inside the composition. Apex `/users/{username}` stays the standalone SNDBNK profile. Reserved flat-page slugs cannot collide with platform routes.
- Client upload autofill uses `#lib/media/audio-metadata.js` (`music-metadata`); server-side tag gap-fill and optional write-back use `#lib/server/media/embed-tags.js` (`taglib-wasm`). Playback must stay resilient across local, SSH, and future storage adapters (no hard-reload required to start the next track). Library quota meter shows the SSH hostname instead of `Hosted` when the SSH adapter is active.
- Artists can mutually link accounts (Settings → Linked Accounts; cap 4) for trusted switching between monikers; the avatar menu lists approved peers and switches via better-auth `multiSession` plus `/linked-account/switch` without signing out.
- `vite.config.js` forces runes mode for every non-`node_modules` file and pins the dev server to port 5174; local auth requires `ORIGIN` / `PUBLIC_BASE_DOMAIN` to match that host (a stale `ORIGIN` on another port fails sign-in with a redirect home and no session). Import icons from `@tabler/icons-svelte-runes` using per-icon paths (`@tabler/icons-svelte-runes/icons/heart`); the plain `@tabler/icons-svelte` package is Svelte 4 (`$$props`) and fails under runes, and barrel imports make Vite compile the whole icon set.
- The accent color is global: the `accent` writable in `#lib/stores/brand.js` drives `--accent` / `--on-accent` (defaults in `src/routes/layout.css`), with preset swatches plus a custom color via an inline slide-down picker; listener account menu and builder Inspector share `#lib/components/ThemeControls.svelte` (tenant appearance also includes `user`; persona palettes expose `--theme-*` tokens); UI typefaces are tokenized in `layout.css` (`--font-body` KoHo, `--font-editorial` Space Grotesk, `--font-display` Audiowide, `--font-lcd` Jersey 20); do not hardcode family names or the accent hex in components; default social/Open Graph image is `/sndbnk-og-image.webp`. Shared SEO via `#lib/components/SeoHead.svelte` + `#lib/seo.js` (canonical, OG/Twitter, JSON-LD); dynamic `robots.txt` and apex-only `sitemap.xml`; `noindex` on feed, library, settings, and auth pages.
- Waveforms use Wavesurfer with SoundCloud-like two-tone bars; progress fill is the live accent, hover/seek preview is a reduced-opacity accent, and the duration chip uses accent background with contrast-aware text. They must redraw to the outer container width on resize (container `ResizeObserver` + `min-width: 0` in flex/grid parents) so the full waveform stays visible instead of clipping. When zoomed in, auto-center should follow playback smoothly. Peak generation for large uploads is async via BullMQ so request handlers stay responsive; the worker also dual-writes the same peaks to `waveform.json` in the track folder via the storage adapter (local and SSH).
- Every paged track listing shares one kit: keyset cursor helpers in `src/lib/server/cursor.js` (bidirectional, optionally inclusive), `serializeTrackRows()` in `src/lib/server/tracks.js`, a single `GET /api/tracks` with `feed` / `library` / `profile` (and likes/history) scopes returning mixed `{ kind: 'track' | 'playlist' }` items, and on the client `TrackList` (`src/lib/lists/track-list.svelte.js`), the `whenVisible` attachment (`src/lib/lists/infinite-scroll.js`), `InfiniteList.svelte`, and `restorableList()` paired with SvelteKit's `export const snapshot`. Feed keeps ALL/FOLLOWING plus compact `q` search end-aligned on the titles row (accent-shadowed input, overlay clear `X` when active; mobile icon-only until expanded). Counted plays use layout-loaded thresholds (`#lib/player/play-thresholds.js` from `platform_settings`, default 60% of duration or 10 minutes of accumulated playing time for mixes; pauses OK, seeking does not count), `POST /api/tracks/[id]/play` bumps `track.playCount` and upserts `listen_history` for signed-in users. Playlists (`playlist` / `playlist_track` / `playlist_like`) are ordered collections of any published tracks; `PlaylistCard` uses one waveform chrome plus a connected member list with per-row cover thumbs; comments post to the active track; playlist likes are separate from track likes; routes under `/playlists/*` and `/api/playlists/*`.
- Scroll restore keeps only a cursor plus pixel offset (never loaded rows), measures via the `offsetTop` chain (not `getBoundingClientRect()`, because the `rise` entrance transform skews rects), binds the list scroll `container` with `$state.raw()` so the DOM handle stays reactive without proxying, and re-observes short-row IntersectionObserver sentinels that can stall inside `rootMargin`; verify infinite scroll in a foregrounded tab or via the rendering-independent `Load more` button.
- Billing is Stripe-backed with DB-managed Free/Vault/Studio/Label plans that gate Free by track count (Free = 15 tracks, no hosted byte cap) and paid tiers by hosted storage bytes, BYO adapters (all tiers), subdomains (Vault+), and custom domains / unbranded (Studio+); when a track or storage cap is hit, uploads are blocked and upload CTAs route to Settings → Billing; checkout lives on `/plans`, webhook at `POST /api/stripe/webhook` (`https://sndbnk.com/api/stripe/webhook` in prod), staff manage plans/coupons/users/play thresholds at `/admin` (plus internal business-plan HTML docs at `/admin/docs/{slug}`), and `bun run stripe:bootstrap` syncs Stripe products/prices into the `plan` table — env keys alone leave paid tiers as “Not available yet” until `stripe_price_*` IDs are written. `PUBLIC_STRIPE_PUBLISHABLE_KEY` is the Standard `pk_` key; server billing uses a restricted secret key.
