1. North star

SNDBNK is a SoundCloud-style audio host with a sharper job: help creators put sound online with a real address, keep files where they want them, and actually enjoy the listening chrome — waveforms, a persistent header player, Milkdrop when the vibe calls for it.

The live brand already says it:

  • Eyebrow: A place for sound
  • Hero: Punch it in. Turn it up.
  • Pitch: An audio multi-tool for both artists and creative listeners
  • Loop: host → store → tag → visualize → post — any sound, not just “tracks for the algorithm”
Maker, not enterprise DAM Built by The American Spreadsheet Co. Indie energy, Winamp-adjacent chrome, ownership over lock-in. You’re not chasing corporate media-asset management — you’re building the tool you wish existed for vibes and catalogs.

3. What’s shipped

You’re not staring at a mock. Production is live on sndbnk.com. Treat this as proof you can ship — then aim the next weeks at conversion and trust, not greenfield fantasy.

You already have a real product The gap is not “can this exist?” — it’s finish the Free promise (cloud BYO), polish the Studio conversion path, earn a handful of paying creators, and keep the box trustworthy before you advertise hard.

4. How it makes money

Seeded catalog (USD; yearly ≈ 20% off). Admin can edit amounts later; paid tiers stay “Not available yet” until monthly and yearly Stripe price IDs exist (bun run stripe:bootstrap).

Plan Monthly Yearly Hosted storage Unlocks
Free $0 $0 1 GB Path profile, unlimited tracks, BYO (SSH now; S3/R2 promised)
Vault $5 $48 30 GB you.sndbnk.com + site edit
Studio $14 $134 150 GB Custom domain, remove branding — featured “full power” tier
Label $35 $336 500 GB Teams (5 seats seeded; UI not built yet)
  • Hosted quota meters local adapter bytes only — BYO is the Free escape hatch.
  • BYO adapters are allowed on every seeded tier; track caps are unlimited by default.
  • Economic center of gravity: Studio (domain + unbranded). Vault is the on-ramp. Label waits until Studio conversion is real.

5. Wedge vs incumbents

Do not try to beat SoundCloud at discovery network effects. Win on ownership tooling plus a listening UX people actually want to keep open.

SNDBNK lean Typical platform lean
Creator owns the URL (path → subdomain → custom + unbranded) Platform-first URLs / marketplace framing
BYO storage (SSH live; S3/R2 next) Files live on the platform only
Unlimited tracks on Free + small hosted quota + BYO Free tiers capped hard or ad-driven
Library as file-manager / multi-tool (tags into files) Stream-social UX first
Milkdrop / Winamp-ish chrome Standard web player
Closest wedge in one line SoundCloud listening UX + Bandcamp-like ownership + self-host option.

Explicit non-goals (for now)

  • Native mobile apps
  • Listener tip jars / download store / full marketplace
  • Heavy personalized discovery algorithms
  • Multi-region / multi-box architecture

Say no so the next six months stay sharp.

6. How it runs today

Single AWS Lightsail box. Cheap, shippable, honest. Don’t plan like a multi-region platform until the product forces it.

Layer Reality
Host sndbnk.com · SSH ubuntu@sndbnk.com · /var/www/sndbnk
Runtime Bun + svelte-adapter-bun → build/index.js on :3000
Edge Caddy: apex certs; *.sndbnk.com + custom domains via on-demand TLS
Data SQLite on disk; deploy backs up then migrates
Media & jobs Local MEDIA_ROOT + optional SSH; Redis + BullMQ waveform worker
Mail AWS SES Mail Manager in production
Deploy GitHub Actions → SSH on push to main

7. Risks & hygiene

These are real debts from docs/known-issues.md — not vibes. Clear them before a growth push.

Item Risk Why it matters
Former secrets still in old git history Medium .env is untracked; rotate BETTER_AUTH_SECRET / STORAGE_SECRET (logs everyone out; invalidates stored SSH creds) before advertising hard
CSP is Report-Only Medium Inventory Butterchurn / Stripe / Fonts, then flip to enforcing when production reports are clean
Stripe price IDs missing Medium Paid tiers show “Not available yet” until bootstrap writes monthly + yearly IDs
S3 / R2 adapters stubbed Medium Marketed on Free; enabled: false — Free promise incomplete
Label teams UI missing Low (for now) Seats seeded; don’t sell Label hard until product exists
Before any advertising push
  1. Untrack .env and rotate secrets.
  2. Confirm Stripe bootstrap + webhook (https://sndbnk.com/api/stripe/webhook).
  3. Smoke-test signup → upload → play → like/comment → sign out on production.

8. Focus next

Ordered on purpose. Resist skipping ahead to Label teams or discovery science while Free and Studio still have holes.

1
Trust & launch hygiene

Untrack/rotate secrets. Confirm Stripe + webhook in prod. Tighten CSP when report-only is clean. Don’t pour traffic on a shaky trust story.

2
Finish the Free promise

Implement S3/R2 BYO adapters so Free isn’t “SSH or 1 GB hosted only.” This is the ownership wedge on the card people actually read.

3
Earn Studio

Polish custom-domain verify, site branding, and unbranded as the conversion path. Studio is the economic center — make that flow feel inevitable.

4
Grow with proof

Get a handful of real creators onto Vault/Studio. Fix the sharp edges they hit — signup pattern console noise, empty states, reliability — not hypothetical scale problems.

5
Then Label teams

Seats exist in the plan table; product doesn’t. Build teams only after Studio conversion is real and someone is asking for seats.

6
Deliberately later

Listener monetization, native apps, heavy discovery algorithms, multi-region. Park them. Revisit when the wedge is paying for itself.

9. Operating cadence

Attach the dream to a weekly habit, not a fantasy backlog. When stuck or tired, shrink the unit of work.

When stuck / when tired
  1. Ship one vertical slice — one visible improvement an end user can feel.
  2. Smoke-test the core path: /signup → /library (drop/pick upload) → play on profile → like/comment on /tracks/{id} → sign out → /signin.
  3. Check light and dark if you touched anything visual.
  4. One conventional commit. Leave the branch cleaner than you found it.

Technical docs stay in the rest of docs/. This page is the why and the order — not the how.
